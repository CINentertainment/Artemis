Desktop listener

Run the one-time Setup-Voice-Activation.ps1 script first. Start the listener to open its desktop panel and activate your microphone. The browser can then close. Minimize the desktop panel to keep listening; closing it quits the listener. Use either panel to mute or stop speech. Avoid enabling the older browser hands-free mode at the same time.

The speech worker now stays loaded and prepares later chunks during playback. Output-device changes apply to the next spoken chunk. Microphone settings apply when the listener next opens the input device; quit and restart after changing them. This uses local speech recognition for wake-phrase spotting, not a separately trained custom wake-word model. For “hey” phrases, a local Whisper check confirms the complete wake phrase before a command is accepted. If recognition remains poor, “hey assistant” is an alternative. The setup script checks vocabulary when supported. Microphone accuracy and interruption depend on your hardware and room; a headset reduces playback pickup.

Connection and recognition details

Start the listener, then use Test spoken output to check synthesis/playback. Listen now records one command without requiring the wake phrase. Both controls reuse the installed local models.

Calibration measures three seconds of quiet input and saves a speech threshold. The default silence delay is 0.55 seconds; increase it if phrases are cut off. Speaker mode suppresses recognition during playback to avoid self-triggering. Headphone mode enables wake-gated interruption; it is not acoustic echo cancellation.

Commands
  • “Hey Artemis, read my brief” — reads the latest saved summary, with available case and market sections (bounded reading length).
  • “Prepare a new brief” — queues the saved briefing routine.
  • “What changed overnight?” or “System status” — reads the current saved change/worker status.
  • “Investigate [topic]” — asks for “confirm research” before queuing collection and a new investigation board.
  • “Ask about [topic]” — opens a continuing conversation over saved briefing evidence and referenced notes. See Voice conversations for the transcript, references and corrections.
  • “Start conversation” / “End conversation” — start a fresh evidence snapshot or end the session.
  • “Where did that happen?” / “Which note supports that?” — ask follow-up questions using the wake phrase each time.
  • “Look into that further” — proposes research on a source-grounded phrase from the last answer; still requires “confirm research”.
  • “Pause market monitoring”, “Resume market monitoring”, “Pause daily briefing”, “Resume daily briefing”.
  • During playback, say the wake phrase, then “pause”, “resume” or “stop”. The desktop/web buttons remain available if spoken interruption is unreliable.
Ordinary commands need the wake phrase each time. A pending research confirmation opens a short response window. Voice does not delete data, trade, execute arbitrary scripts or provide speaker authentication. Microphone audio is held in memory and sent only to the existing local transcription endpoint.
