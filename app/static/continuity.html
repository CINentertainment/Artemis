Last verified backup

Verification checks authenticated encryption, SQLite integrity, foreign keys, row counts and an in-memory Windows encryption rebind rehearsal. It does not prove recovery on a different physical machine or make a simultaneous transaction across all four applications.

Scheduled encrypted backups

Choose a separate drive or another independent copy location where possible. A backup on the same disk does not protect against that disk failing. Archives are passphrase-encrypted before writing.

Discovery checks only known project folders. If multiple or no candidates appear, enter the actual live SQLite path. Companion database paths are your explicit configuration; do not choose source-code files or an old backup.

Keep this passphrase independently, such as in your password manager. The local automatic-backup credential is Windows-user protected and is deliberately excluded from the backup.

Verified staged recovery

Restore to a NEW folder first. This decrypts the archive, checks each database and re-encrypts Artemis-protected values for the Windows account performing recovery. It does not replace live data.

.\.venv\Scripts\python.exe -m app.vault_restore --archive "E:\CIN-Backups\BACKUP-ID.arb" --output "E:\Artemis-Restore-Rehearsal"

Enter the recovery passphrase when prompted. Inspect restore-report.json and the staged databases. For live database activation, stop Artemis, the remote gateway, Intel Notes, Risk Tracker and Market Lens first, then use the explicit activation command in README. Existing schema must match; a verified pre-restore snapshot is saved. Settings and reports remain staged for review.

No restore or data deletion is exposed to the remote portal. No plaintext portable archive is written during backup; staged restored files contain sensitive application data and must be protected.
